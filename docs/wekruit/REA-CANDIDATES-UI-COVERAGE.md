## Actual-data restrictions

- Saved sequence associations do not always contain enrollment date, added-by or sender; sync time is labeled as sync time. Missing values are not substituted with account identity or current time.
- No profile coordinates are stored, so Insights does not manufacture a geographic map. It shows the supplied location distribution. Missing languages, majors and dated work history remain unknown.
- Missing recipient addresses are explicitly unknown. Work/private-email classification, enrichment provenance, pricing and charges are not invented. The handoff requires resolving missing addresses and obtaining final existing approval before any sending.
- A requested start is presented as wall time plus the selected IANA zone; the existing agent/service must validate that request and current campaign configuration before activation. The preview does not claim an uncomputed UTC instant.
- No paid lookup, review delivery, campaign activation, message send or external invitation was used as fixture acceptance.

## Saved-media inventory and historical repair

Contacts reads `recruiting_saved_profiles` only for the returned page's exact person keys, with both `ownerUserId` and `spaceId`; the shared contacts page maximum is 100. This projects retained data directly and needs no data migration or historical rewrite. The DTO carries the complete validated saved profile, photograph and explicit employer/school media for web, desktop and later native clients. Employer media is selected only for the displayed employer; ambiguous URLs remain absent. Detail/timeline reuse that same saved profile and existing image/organization helpers.

For older omitted projections, the existing authenticated RPC now accepts a read-only inventory request:

```ts
const inventory = await rpc.recruiting.fillRoleProfiles({
  roleId: selectedOwnedRole.id,
  dryRun: true,
});
```

Run this through the normal authenticated application client for the selected role. The server derives the actor/space from the session; callers do not supply another person's identity. `dryRun:true` does not fetch photographs, dispatch connectors or save profiles. No production inventory was run as implementation evidence.

The existing path is `listRecruitingRolePoolRuns` (owned role → exact LinkedIn pool keys → owner/space-scoped candidate-page runs), then `listRecruitingSavedProfiles`, then retained completed catalog-tool effects. The effect count and each read require actor user/space. Source connections must still belong to that actor/space. All retained eligible effect pages are scanned oldest first, with at most 400 effects per database read; the previous total 400-call ceiling has been removed. Existing provider parsers check exact LinkedIn person identity. No paid search or lookup is dispatched.

`inventory.missingBefore` and `inventory.recoverable` count people for `photo`, `work`, `education`, `employerLogo` and `schoolLogo`. Work/education mean a nonempty retained history; logo means at least one logo in that person's corresponding history, not complete media for every occurrence. `recoverable` counts an initially missing field available from the parsed retained results. In dry-run mode the legacy `filled/photos/missing` values describe the simulated repair, not writes. `sourceCalls`, `sourcePageSize:400` and `sourceCoverage:"owned_saved_results"` disclose the scope. These are not counts of external provider completeness or current photo-download success.

After reviewing that inventory, the same existing RPC with `dryRun:false` performs the repair for that exact owned role. It preserves existing full work/education and all nonempty saved media; fills missing histories from retained facts; and fills absent organization media only for matching normalized organization names with no contradictory known site URL and one unambiguous retained URL. Each save validates the exact completed source effect/run again. Photo copying uses the existing URL and image guards; failure cannot create a fictional image. The ordinary `keepSearchHistory` path also now repairs a missing inline photo when work and education already exist.

True data restrictions remain explicit: plain text work/education lines contain no organization logo; supported structured profile records can supply actual employer/school logos. Unrecognized source shapes, disconnected/deleted source connections, parser bounds (structured provider histories: 80 jobs/40 schools; search histories: 30 entries) and genuinely absent fields are not proof that no original record exists elsewhere. Original effects/artifacts remain unchanged. Counts do not infer URLs, profile photos, education, phone/email, or newly verified contactability. Staging acceptance must record the selected role, returned inventory, any authorized repair and the resulting same-person list/detail images separately from this local code evidence.
