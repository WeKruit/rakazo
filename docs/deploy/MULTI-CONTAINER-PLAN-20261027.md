# 从一个容器到多个容器：剩下要做的事（2026-10-27）

属于架构差距清单的第 1 项（[ARCHITECTURE-GAPS-ITEM1.md](./ARCHITECTURE-GAPS-ITEM1.md)）。代码依据是 rakazo main `b63b31d6`（#262 合并后）。

## 为什么现在只能有一个容器

只要下面任何一条还在，就不能开第二个容器，也做不了滚动发布：

| 状态 | 现在存在哪里 | 线上大小 | 开第二个容器会出什么事 | 状态 |
|---|---|---|---|---|
| 附件文件 | 本地卷 `artifacts/` | 217 MB | 另一个容器读不到 | #260 已合并，等你同意建存储桶和改 Secret |
| 电脑工作目录和检查点 | 本地卷 `homes/`（`LocalAgentHomeStore`） | 114 MB | 两个容器各写一份，数据会分叉 | #262 已合并：设了存储 Secret 后每次写入同步到桶，读之前比对版本 |
| MCP 连接授权时还没完成的登录 | 复查后：已经存在数据库里 | — | 没问题 | 不需要改 |
| 模型账号登录（应用内订阅登录） | 进程内存（`pi-oauth.ts` 的 `PiOAuthLogins`） | — | 登录要在发起它的那个容器完成 | 未改；令牌刷新复查后已用数据库行锁，没问题 |
| 手机推送 token | 本地卷 `push-tokens/` | 几百字节 | 推送丢失 | #262 已合并：改存数据库 |
| 其他私有文件 | 本地卷 `private/` | 3.2 MB | 待查是什么 | 未查 |

## 做法

1. **工作目录。** 写一个用对象存储的 `AgentHomeStore`：每次 commit 把整个目录打成一个快照对象，`homes/<key>/current` 指向最新的快照。有 3 处代码绕过接口直接操作本地路径，要一起改成走接口：`child-bots.ts` 删除专属电脑和清理团队文件夹的地方，以及 `computer-lifecycle.ts` 的 `mkdir`。这块涉及沙盒和符号链接的安全检查，必须带测试。迁移方式和 #260 一样：新写入进存储，旧的从卷上读，最后跑一次拷贝。预计 2–3 天。
2. **还没完成的登录。** 把 pending 状态存进数据库（已经有 `createdAt` 的 TTL 查询可以复用），回调到哪个容器都能完成。令牌刷新改用 Postgres advisory lock 协调。预计 1–2 天。
3. **推送 token** 改存数据库。新加一张表，属于加法迁移。半天。
4. **拆服务。** `app.py` 拆成 web+API 和 worker 两个 Modal 服务，`max_containers` 大于 1，去掉 `nonpreemptible` 单写入者的限制。然后做滚动发布。1 天，加上一次发布验证。

前三步互不依赖，可以并行。第 4 步要等前三步都上线、验证过之后才做。

## 需要你同意的

- 存储桶加 3 个 Secret 值（附件和工作目录共用同一个桶）。
- 第 4 步改变部署形态，要单独发布一次。
