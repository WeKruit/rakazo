# Required CRM role correspondence

Development base: `4a3e8e11`. This commit contains only synchronization error handling, the managed Main default, regression tests, and this delivery note. The API companion change is `51ddbff6496a1d35504e42eb9d5f313550f1fdf6`; integrate both for complete error semantics.

Role correspondence is a required synchronization phase. An unsupported source response or any read/authorization failure now fails the current slice. It does not advance to the next role, consume the saved cursor, or report completion. The transaction preserves the prior offset/token and rolls back that slice's writes. After the real source capability or authorization issue is resolved, retry the same cursor within its existing validity period; otherwise start a new pass. A deployment does not imply that existing source permissions have been granted.

Fresh managed Main defaults include `list_crm_role_correspondence`; Sourcer defaults are unchanged. Existing assignments upgrade only when their stored managed signature still matches. Customized tool lists, explicit revocations, and removed assignments remain untouched. No production permission was granted by this development work.

For an existing restricted assignment, the pending authorization request is only the exact read-only `list_crm_role_correspondence` tool on the current caller's existing CRM server assignment. Resolve the actual coordinator from the authorized thread target (the bot target, or the first group member used by the service), not a displayed bot name. Retain the exact owner, Space, bot, and server identifiers; keep `allowAllTools=false`, all existing restrictions, and every unrelated assignment. Do not grant all recruiting bots or add sending/calendar permissions. This note is a proposal for review, not permission to execute the grant.

Read-only diagnostic order: verify the current workspace and CRM reference; compare requested versus effective role arguments; inspect the exact source campaign mapping; read a known stored-mail sample through the assigned source tool; then check terminal synchronization errors, cursor, and totals. A zero message count is not evidence of no source mail when the required read was denied or unsupported. Source table raw counts are not projection totals; compare the same authorized role scope and distinct message IDs. Do not navigate a deployed application or run a sync from the development environment.
