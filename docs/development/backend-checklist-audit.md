## Native calendar changes follow-up

The native Cal.com reschedule/cancel path retains a typed `calendarApprovalEvidence` object in the existing **intended** effect result, written once with an intended-status/database-null compare-and-set. This is approval evidence, not a successful provider receipt. It includes exact source/revision/tool, request fingerprint, original UID, event type, status, times, full attendee/host records and supplied title/description/location/meeting URL. The native card displays the original alongside the unchanged proposed arguments; oversized evidence fails instead of silently truncating approval context. The card hash is copied into the genuine answer event after verification under an effect row lock. Replay requires that exact answer proof and unchanged request, then re-reads the original from the same freshly authorized assigned source. Legacy official Cal cards without evidence cannot be allowed; denial remains usable. Successful provider completion replaces evidence with the real outcome through the existing effect lifecycle.

Rescheduling requires an explicit proposed UTC start and positive `lengthInMinutes`, plus discovered `get_availability` schema accepting the exact original booking exclusion UID and interval fields. Cancellation verifies the unchanged original and does not invent recurrence scope; `cancelSubsequentBookings: true` is unsupported. Both paths reject changed original identity/content/participants or missing evidence. A timeout keeps the existing uncertain-effect no-retry boundary. A later exact `get_booking` read uses the latest successful or possibly dispatched (executing/uncertain) matching mutation effect ID and status as a durable cache epoch, scoped to actor/thread/source/revision/UID; prior receipts remain intact and actual provider arguments remain unchanged. This prevents a pre-cancellation booking receipt from being reused as post-cancellation or post-timeout reconciliation readback. An uncertain attempt only expires the read cache; it never proves success or booking ownership, and mutation replay remains blocked.
