# Other retained observations and limits

These points come from the six complete source-owner reports. They were read as text; the original private files were not opened by this checkout.

- A newer existing fundraising research record from 2026-10-19 had a 5,121-byte prompt and ten returned rows with partial outcome. The provider described eight supported and two unresolved rows; this was not independently checked and is not a Grok comparison. It shows why returned count and qualification must stay separate.
- A separate 2026-10-19 existing reply asked only to verify one retained person's location, with no new candidates. The owner located the native receipt and returned version. This is counterevidence to a blanket claim that every feedback continuation adds people; it does not prove all prompts honor scope.
- A 2026-10-21 source-lineage investigation retained three pages of sixteen rows but lacked the `_sources` map; a wording-only rewrite lost some opaque source IDs. This is a provenance-preservation issue, distinct from a claim that Autumn's search itself was poor.
- The older thirteen-question benchmark explicitly recorded extraction OR/AND mistakes, contamination and insufficient cache/budget isolation. Its direct-versus-product scores cannot be reused as a fair Grokbot-versus-Rakazo experiment.
- The old PLAN export census was useful for locating history, but it is not a complete index of the newer session. The source owner located additional material independently. Public-safe source digests are retained in [source-metadata.json](source-metadata.json); original paths remain private.

The Grok method notes also describe code deduplication with LinkedIn normalization and a name fallback, plus agent verification of evidence/tenure and reclassification of provider A grades. Those are source-agent descriptions, not independently executed code. Rakazo's native identity checks and “provider owns ranking” policy therefore have a different verification responsibility; comparing only final A/Strong counts would confound the systems.
