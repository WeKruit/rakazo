## Phase Details

### Phase 1: Real sourcing and recruiting UI
**Goal:** A recruiter uses the actual role and connected Autumn agent to research people, inspect evidence, give feedback and see continued research and saved results in the same workspace. Native Main/Sourcer automation retains its original Crew and role.
**Depends on:** Existing deployed Rakazo/Pi, authorized model and Autumn connection.
**Requirements:** Playbook S1–S5; scope I01–I06, J01–J11; native group/routine continuity.
**Success Criteria:**
1. Actual Autumn calls and returned evidence, source references and complete result pages are observed and saved; mock or demonstration conversations cannot satisfy product acceptance.
2. Human feedback is distinguished from candidate qualification and is reflected in subsequent research on the original Autumn task.
3. Role and candidate UI uses business content, preserves exact evidence and unknowns, and retains original question/approval ownership.
4. Routine creation, manual run, scheduling, delegation and result delivery use native capabilities and preserve the intended original group/role; no second scheduler or harness.
**Plans:** See the active delivery batch in PLAN.md. Independent UI, native routine and live Autumn work execute in parallel.

### Phase 2: Recruiting workspace
**Goal:** Finish the existing J/M recruiting workspace action matrix using actual persisted records and ordinary user actions.
**Depends on:** Phase 1 for complete sourcing acceptance; independent UI work can run earlier.
**Success Criteria:** Applicable J/M actions have direct user-flow evidence.

### Phase 3: Complete agent collaboration
**Goal:** Reuse native Rakazo collaboration and configuration to cover applicable A–H actions and each specialist's actual responsibilities.
**Depends on:** Existing native runtime; independent work can overlap Phases 1–2.
**Success Criteria:** Bot capabilities, integration status and actual business completion are recorded separately; original interactions and authorization survive recovery.

### Phase 4: Recruiting service workflows
**Goal:** Complete remaining playbook S6–S13 and M4 integrations after sourcing, without rebuilding external agent/service capabilities.
**Depends on:** Actual sourcing results and authorized existing services.
**Success Criteria:** Each native specialist has observed read/write and handoff outcomes; real outreach retains exact native approval.

### Phase 5: Full-product acceptance
**Goal:** Finish M5 without equating a local implementation or a narrow check with the full product.
**Depends on:** Phases 1–4.
**Success Criteria:** Every applicable scope action has evidence or an explicitly accepted deferral; no unresolved critical business path is marked complete.
